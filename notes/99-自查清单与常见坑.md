4. GQA 里 `repeat_kv` 的 `expand + reshape` 为什么比 `repeat` 省显存？
5. QK-Norm 解决了什么问题？为什么 RL 阶段更需要它？

## 常见坑：按症状查病因

| 症状 | 最可能的原因 | 去看 |
|---|---|---|
| loss 直接变 0 或 nan | mask 全 -100 / 学习率过大 / bf16 下 RMSNorm 溢出 | `lm_dataset.py`、`trainer_utils.py` |
| 模型不会停，一直输出 | `<eos>` 被 mask 掉 | `SFTDataset.generate_labels` |
| 模型自问自答 | 问题部分没 mask | 同上 |
| `load_state_dict` 之后效果和没加载一样 | `--from_weight` 拼错，`strict=False` 静默跳过 | `init_model` |
| 保存的权重 key 带 `module.` / `_orig_mod.` | DDP / compile 没解包 | `lm_checkpoint`、保存段 |
| DPO 开局 loss 不是 0.693 | policy 与 ref 不同权重 / batch 顺序乱 | `train_dpo.py` |
| PPO 训练中途卡死 | 早停时某卡 break，DDP 集合通信错位 | `train_ppo.py` 的 `stop_ppo` |
| GRPO 的 advantage 全是 0 | 一组样本分数完全相同（全对/全错） | `grouped_rewards` 那段 |
| RL 后模型变复读机 | 长度奖励 / 重复惩罚权重失衡，reward hacking | `calculate_rewards` |
| 多轮训练 loss 不降 | `logp_pos` / `old_logps` 少了那个 `-1` | `train_agent.py` 打包段 |
| sglang 后端报权重没更新 | `update_policy` 没在所有 rank 调用 | `rollout_engine.py` |
| 流式输出偶发标签错乱 | 标签被切在 chunk 边界，缺 pending 缓冲 | `serve_openai_api.py` |
| 推理效果比训练时差很多 | `open_thinking` / chat template 与训练不一致 | `tokenizer_config.json` |

## 如果你要自己改这个仓库，建议的顺序

1. **先改数据，不改模型**：换一份 SFT 数据，跑一遍，感受 loss 曲线。
2. **再改 mask**：故意把 prompt 也算进 loss，看看模型怎么坏掉（最快建立直觉）。
3. **再改 loss**：把 SFT 的 CE 换成「只算最后 100 个 token」，对比效果。
4. **最后才动结构**：改层数 / 头数 / intermediate，重算参数账本。
5. **RL 部分建议先跑 GRPO 再碰 PPO**：前者没有 critic，故障面小一半。
